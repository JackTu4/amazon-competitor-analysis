# 智能竞品分析系统 -架构文档
    分为 4 层：**应用 Agent 调度层、大模型层、工具层、数据输出层**
# 1.Agent 调度层（核心调度）
    1.用户输入接收模块：接收用户输入的两个 ASIN 竞品
    2.需求解析模块：LLM 识别用户意图，解析需要采集哪些字段；判断是否需要调用工具
    3.工具规划模块：决定调用顺序：优先 Amazon 商品数据工具，再调用网页搜索补充；处理工具返回结果；简单异常重试（工具调用失败）
    4.结果组装模块：汇总全部工具返回的数据，交给 LLM 做分析
# 2.大模型层（LLM）
    1.意图解析：解析用户输入 ASIN，识别分析任务
    2.内容分析 & 文本生成：基于工具返回的原始数据，做竞品对比推理；生成最终 markdown 报告正文；标注信息来源
# 3.Tool工具层（两个核心工具）
    1.Amazon Product Data Tool
      输入：ASIN 编号；输出：商品结构化原始数据（标题、五点描述、星级评级、价格、评论样本、asin）
    2.Web Search Tool
      输入：竞品名称 / ASIN；输出：互联网公开补充竞品资料（第三方评测、市场反馈）
# 4.数据输出层
    报告生成模块：接收 LLM 分析结果，按固定模板输出 markdown 格式本地文档；保留每条内容对应的信息来源
# 模块之间数据流
    用户输入(2个ASIN)
      ↓
    Agent调度层（解析需求，规划工具调用）
          ↓
    ├─调用Amazon Product Data Tool → 获取亚马逊商品结构化数据
    └─调用Web Search Tool → 获取外部网页补充信息
          ↓
    全部原始数据回传给Agent
          ↓
    提交全部原始数据送入LLM
          ↓
    LLM完成竞品对比分析
          ↓
    输出层生成Markdown竞品分析报告（附带来源）
# 架构约束（MVP 阶段）
    1. MVP 无持久化数据库：所有数据内存流转，报告只输出本地 md 文件，不存数据库
    2. MVP 无 web 服务，以脚本 / 命令行形式运行
    3. 不实现并发，一次只处理一组（2 个）竞品 ASIN 任务
    4. 工具返回失败时 Agent 只做简单提示，不做复杂容错重试
# 接口简要说明
    1. Agent ↔ Amazon Product Data Tool：入参 ASIN 字符串；返回 json 结构化商品字段
    2. Agent ↔ Web Search Tool：入参搜索关键词；返回网页文本片段 + 网页来源 url
    3. Agent ↔ LLM：入参 prompt + 全部工具返回原始 json 数据；返回分析后的报告文本
