01一句话结论

一次分析任务的完整链路是：

Vue 组件 → frontend/src/api/analysis.js（fetch 封装）
         → Vite 代理 /api → FastAPI（backend/app/main.py 路由）
         → analysis_service.py（内存任务表 + 后台线程）
         → AnalysisWorkflow（3 个 Task 串联）
         → Agent（LLM + 工具循环）+ 竞品发现 + 报告生成
         → reports/{task_id}.md
         → 前端 2 秒轮询 → GET report → markdown-it 渲染
核心判断 这是一个「提交任务 → 后台线程执行 → 前端轮询 → 拉取报告」的异步任务模型。 HTTP 层只做三件事：创建任务、查状态、取报告；真正的业务全部发生在后端进程内的线程与工作流中， 任务状态保存在内存字典，报告以 Markdown 文件落盘。

07前后端接口实现文件（重点）

前后端之间只有 3 个 HTTP 接口，全部定义在 backend/app/main.py：

POST /api/analysis
用途
创建分析任务，立即返回 task_id
请求体
{ "target_product": "HUADISK 256GB SSD" }（AnalysisRequest）
响应体
{ task_id, status:"pending", message, target_product }（AnalysisResponse）
处理函数
main.py:31 create_analysis → analysis_service.py:68 create_analysis_task
前端调用
api/analysis.js:3 createAnalysis
GET /api/analysis/{task_id}
用途
查询任务状态（前端每 2 秒轮询）
响应体
{ task_id, target_product, status, error }
状态值
pending / running / completed / failed
处理函数
main.py:53 get_analysis_status（直接读 analysis_tasks）
前端调用
api/analysis.js:26 getAnalysisStatus
GET /api/analysis/{task_id}/report
用途
获取 Markdown 报告全文
响应体
{ task_id, status:"completed", report: "..." }
错误码
404 任务不存在 / 409 未完成或失败 / 500 路径无效
处理函数
main.py:73 get_analysis_report → Path.read_text()
前端调用
api/analysis.js:42 getAnalysisReport

另有 GET /health（main.py:21）用于健康检查，前端未使用。

接口契约链路 schemas.py 定义请求/响应模型 → main.py 声明 response_model 并实现路由 → api/analysis.js 以相同的字段名（target_product、task_id、status、report）发起请求与解析响应。 三者之间没有自动生成的类型共享，字段名是手工对齐的。

08数据形态演进

阶段数据结构
HTTP 请求{ "target_product": "..." }
任务表记录{ task_id, target_product, status, result, error }
工作流输入{ task_id, target_product }
竞品发现后+ target_asin、+ competitors: [{ name, asin, url }]
竞品分析后{ task_id, target_product, analyses: [{ competitor_name, competitor_asin, competitor_url, analysis }] }
analysis 字段CompetitorAnalysis Pydantic 对象（或 {"error": ...}），序列化后才进入报告
报告Markdown 字符串
报告接口{ task_id, status, report }
前端渲染report 字符串 → HTML → DOMPurify.sanitize → v-html

线程模型

执行位置并发方式代码
每个任务1 个 daemon Threadanalysis_service.py:78
工作流三步串行analysis_workflow.py:15
竞品分析ThreadPoolExecutor(3)tasks.py:98
竞品发现搜索 / 核验各 ThreadPoolExecutor(3)competitor_discovery.py:55、discovery_parser.py:141

进程内缓存

所有缓存都在内存中，进程重启即失效：网页搜索（web_search.py:9）、网页正文（web_reader.py:15）、 商品提取（extractor.py:3）、评论分析（product_review_pipeline.py:9）、 embedding（rag/embedding.py:9 的 lru_cache）。

09风险清单与修复建议

等级问题位置修复建议
阻断 JS 文件里写了 # 注释，Vite 语法错误，开发服务器无法启动 frontend/vite.config.js:4 改为 // 注释或删除（当前未提交改动）
阻断 <style> 内使用 // 注释，.success 规则可能整条失效 AnalysisStatus.vue:58 改为 /* ... */ 或删除
高 默认 MOCK 模式，真实 Agent 不会执行 analysis_service.py:11 在 .env 显式设置 MOCK_MODE=false；或把默认值改为 false
高 没有 CORS 中间件，生产构建跨域会被浏览器拦截 backend/app/main.py 加 CORSMiddleware，或由 Nginx 反代同源部署
高 任务状态是进程内字典，多 worker / 重启即丢失，且长期运行内存增长 analysis_service.py:12 迁移到 Redis / 数据库，并用 Celery / RQ 等任务队列
中 报告目录使用相对路径，依赖启动目录 reporter/markdown.py:152 基于项目根目录拼绝对路径
中 根目录 main.py 导入了已不存在的 workflow_tasks main.py:4 改用 create_workflow_tasks()，或删除旧入口
中 导入 ProductForm.vue，实际文件为 productForm.vue，Linux 构建会失败 AnalysisView.vue:6 统一文件名大小写
中 报告未标注数据来源，与架构文档要求不一致 reporter/markdown.py:94 在 CompetitorAnalysis 增加 source 字段，并在报告中输出
中 requirements.txt 缺少 fastapi、uvicorn、httpx2 等依赖 requirements.txt 补全依赖或在 pyproject 中声明
低 大量空占位模块（routers.py、services.py、report_generator.py、positioning_analyzer.py、trend_analyzer.py） backend/app、app 实现或删除，避免误导
低 discover_competitors 工具已定义但不在 Agent 的 allowed_tools 中，competitor_tool.py 也未被调用 app/tools/schema.py:47、app/tools/competitor_tool.py 明确是否要走“Agent 自主发现”，否则删除
